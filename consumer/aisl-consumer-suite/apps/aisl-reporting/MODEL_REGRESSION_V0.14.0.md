# Сравнительная модельная регрессия Reporting 0.13.4 → 0.14.0

Проверка выполнена текущей моделью ChatGPT на одинаковых datasets, сформированных builders 0.13.9 и проверенных контрактами 0.14.0. Это не слепой benchmark и не сетевой E2E корпоративного LLM. Цель — проверить редакционную композицию, полноту named facts и расположение ограничений.

## Выводы

- **Модель данных:** новая версия сохраняет полный каталог и declared/observed связи, добавляет обязательную физическую ER-диаграмму и переносит coverage/gaps в приложения. Baseline не содержит ER и получает `missing_required_er_diagram` при проверке по текущему dataset.
- **SQL Source Inventory:** обе версии способны перечислить полный небольшой каталог, но 0.14.0 показывает структуру по схемам, конкретные usage patterns и переносит coverage из основного рассказа в приложение A.
- **Git impact:** 0.14.0 перечисляет все 12 changed paths и все семь semantic delta items, включая exact expressions; baseline показывает только укрупнённую часть изменения.
- Во всех трёх новых отчётах ограничения больше не занимают самостоятельный основной раздел; confirmed facts и named catalogs идут первыми.
- Недоказанные сведения не повышены в статусе: observed JOIN не превращены в FK, unmapped SQL fields не назначены relation, Git runtime/test/downstream facts остаются `not_established`.

## Ограничения регрессии

- Использованы доказательные synthetic fixtures, потому что реальные `report_dataset.json` не были переданы.
- Текущая модель формировала обе стороны A/B и знала цель изменения; это редакционная, а не статистически независимая оценка.
- Все три отчёта 0.14.0 проходят advisory report validation без warnings; baseline сохраняет ожидаемые warnings по ER/evidence.
- Реальный runtime E2E следует повторить на новом задании Analysis UI после публикации revision.
