# UI2 v1.4.0 — безопасное переиспользование результатов анализа

## Изменено

Повторный запуск больше не считается совпадающим только по URL репозитория и идентификатору LLM-профиля.

UI определяет точный commit удалённого репозитория через `git ls-remote ... HEAD` и строит независимые ключи для четырёх стадий:

1. выбора профилей;
2. статического анализа;
3. LLM-анализа;
4. генерации отчёта.

## Ключи стадий

### Выбор профилей

- текст вопроса;
- модель;
- hash профиля `profile-router`;
- версия `evidence-llm-pipeline`.

### Статический анализ

- нормализованный URL репозитория;
- точный commit SHA;
- идентификатор и hash статического профиля;
- версия `code-analyzer-core`.

### LLM-анализ

- ключ и фактический manifest статического анализа;
- идентификатор и hash LLM-профиля;
- версия `evidence-llm-pipeline`;
- модель.

### Отчёт

- ключ LLM-анализа;
- hash фактического `bundle_fingerprint.json`;
- идентификатор и hash профиля отчёта;
- версия `evidence-llm-pipeline`;
- модель.

## Поведение

- тот же commit и те же профили: все результаты переиспользуются;
- новый commit: повторяются статический анализ, LLM-анализ и отчёт;
- изменён статический профиль или анализатор: повторяются статический анализ и зависимые стадии;
- изменён LLM-профиль, pipeline или модель: повторяются LLM-анализ и отчёт;
- изменён только профиль отчёта: повторяется только отчёт;
- одинаковый вопрос и неизменный router: выбор профилей также переиспользуется.

Каждая стадия считается готовой только при наличии атомарно записанного cache manifest и полного набора обязательных артефактов. Незавершённые и повреждённые каталоги не используются.

Старый кэш UI, построенный только по URL, намеренно не переиспользуется: у него нет доказательства соответствия конкретному commit.

## Агентный чат

`/ask` больше не вычисляет bundle по URL и профилю из запроса. Он использует неизменяемый `artifacts_dir`, сохранённый в результате конкретной задачи. Это исключает ответы по bundle другой версии репозитория.

## Пользовательская лента

Добавлены события:

- проверка версии репозитория;
- найденный commit;
- переиспользование выбора профилей;
- переиспользование статического анализа;
- переиспользование LLM-анализа;
- переиспользование отчёта;
- итоговая карта переиспользованных стадий.

## Настройка путей

Удалены жёстко заданные абсолютные пути. По умолчанию ожидается структура:

```text
projects/
  code_analysis/
  code_analysis_ui/
```

Для другого расположения используются переменные `UI_BASE_DIR`, `CODE_ANALYSIS_ROOT`, `LLM_PROMPTS_DIR`, `PACKAGES_DIR` и переменные отдельных каталогов результатов.
