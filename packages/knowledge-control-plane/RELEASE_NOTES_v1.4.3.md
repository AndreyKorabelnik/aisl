# UI2 v1.4.3 — сохранение задач и переписки с агентом

## Что изменилось

Переписка с агентом теперь сохраняется отдельно для каждой задачи анализа и восстанавливается:

- после обновления страницы;
- при повторном открытии задачи из истории;
- после перезапуска backend;
- при продолжении диалога спустя время.

Для каждой задачи создаётся каталог:

```text
backend/task-data/<task_id>/
  task.json
  chat_history.jsonl
```

`task.json` содержит только лёгкое состояние UI и ссылки на неизменяемые артефакты анализа. Полный `final_response.json` в него не копируется.

`chat_history.jsonl` является append-only журналом. Одна строка содержит завершённую пару «вопрос пользователя — ответ агента», поэтому частично записанный ответ не считается валидной историей.

## Независимость диалогов

Диалог принадлежит задаче, а не analysis bundle.

Две задачи могут переиспользовать один и тот же статический анализ, LLM bundle и отчёт, но сохраняют разные истории чата. Принудительный повтор LLM-анализа также получает собственный независимый диалог.

## Контекст модели

Пользователю показывается вся сохранённая переписка. В LLM по-прежнему передаётся только ограниченное последними сообщениями окно согласно:

- `AGENT_MAX_HISTORY_TURNS`;
- `AGENT_MAX_HISTORY_CHARS`;
- `AGENT_MAX_ANSWER_HISTORY_CHARS`.

После перезапуска backend это ограниченное окно восстанавливается из полной истории перед следующим вопросом.

## API

Добавлен endpoint:

```text
GET /ask/{task_id}/history
```

Он возвращает сохранённые сообщения конкретной задачи.

Существующий endpoint:

```text
DELETE /ask/{task_id}/history
```

теперь очищает и память agent runtime, и файл истории на диске.

`POST /ask` возвращает сохранённый `exchange`, чтобы frontend показывал ровно те сообщения и временные метки, которые записаны backend.

## Персистентность задач

Минимальное состояние задачи теперь сохраняется в `task.json`. Благодаря этому после перезапуска backend остаются доступны:

- список завершённых задач;
- отчёт;
- точный `artifacts_dir` для agent runtime;
- пользовательские runtime events;
- переписка.

Задача, которая находилась в состоянии `starting` или `running` во время остановки backend, после запуска помечается как прерванная. Автоматически продолжать оборванный subprocess небезопасно.

## Конфигурация

По умолчанию данные сохраняются в:

```text
backend/task-data
```

Путь можно вынести за каталог установки UI:

```dotenv
UI_TASK_DATA_DIR=/absolute/path/to/persistent/ui-task-data
```

Это рекомендуется, если при обновлении UI каталог приложения удаляется целиком.

## Безопасность

Файлы задач и чата создаются с правами `0600`, каталоги — `0700`. В историю не записываются сертификаты, токены, системные промпты или результаты evidence tools; сохраняются только пользовательский вопрос, финальный ответ и ссылки на evidence.
