# Analysis UI 2.0.0a50

## Исправления

- SQL-витрина больше не материализуется повторно через `materialize-knowledge-layer --task-id sql-mart`.
- Для SQL-пайплайна публикуется канонический Knowledge Layer, который уже создан командой `static-analysis-runner repository --materialize-knowledge`.
- Предпросмотр CLI отражает тот же путь и не показывает лишнюю стадию повторной материализации.
- Повторный запуск и кэш учитывают, что repository-анализ может сам создавать Knowledge Layer.

## Человекочитаемые названия

- В публичный контракт задания добавлено необязательное поле `display_name`.
- Analysis UI автоматически формирует названия по назначению и объекту анализа, например:
  - `Модель данных — UCP`;
  - `SQL-витрина — Витрина Профиль ФЛ`;
  - `Физическая модель — CDO B2C PDM`.
- Название отображается в истории задач и в заголовке страницы выполнения.
- При публикации название записывается в `revision.metadata.display_name` и `revision.source.metadata.display_name`.
- Список и карточка ревизий показывают человекочитаемое название, сохраняя технический `revision_id` отдельно.

## Совместимость

- Технические `job_id`, `system_id` и `revision_id` не изменены и остаются стабильными идентификаторами API.
- Старые задания без `display_name` продолжают читаться; интерфейс использует прежние поля как запасной вариант.

## Настройка LLM для отчётов

- `knowledge-reporting` теперь получает тот же endpoint и mTLS-настройки, которые сохранены в конфигурации Analysis UI.
- Backend передаёт совместимые переменные `LLM_ENDPOINT` и `LLM_BASE_URL`; последняя требуется текущему `evidence-common`.
- Относительные пути к сертификату, ключу и CA преобразуются в абсолютные перед запуском subprocess.
- Endpoint и значения TLS-переменных не добавляются в командную строку и не отображаются в журнале или CLI preview.
- Если модель не передана в задании явно, для отчёта используется `llm.default_model` из конфигурации UI.

## Тестовые контракты

- Публикационные проверки одиночного репозитория переведены с недопустимого `data-model-pipeline` на `knowledge-context-pipeline` с явным профилем анализа.
- Ранее известные ложные падения публикационных тестов устранены без добавления legacy-поведения в runtime.
