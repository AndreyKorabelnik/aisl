# Analysis UI 2.0.0a51

## Однорепозиторные стандартные мастера

Стандартные мастера теперь имеют явный контракт одного репозитория:

- `data-model-pipeline:v1` — модель данных;
- `system-description-pipeline:v1` — описание системы;
- `foreign-data-persistence-pipeline:v1` — хранение внешних данных.

Для них Analysis UI:

- предлагает выбрать ровно один репозиторий;
- запускает `static-analysis-runner repository`;
- передаёт фиксированный suite соответствующего мастера;
- включает встроенную материализацию Knowledge Layer;
- использует Knowledge Layer, созданный repository-анализом;
- не создаёт `workspace-selection.json`, `workspace_id` и промежуточный workspace.

Прямой API-вызов со `workspace_id` для этих мастеров отклоняется. Это защищает контракт независимо от frontend.

## Специальные многорепозиторные сценарии

Workspace не выбирается автоматически по количеству репозиториев. Он остаётся частью только тех мастеров, где многорепозиторный контур определён предметным сценарием:

- специальная подготовка контекста UCP через `knowledge-context-pipeline:v1`;
- межсистемные взаимодействия через `system-interaction-pipeline:v1`;
- другие явно объявленные многорепозиторные сценарии.

Мастер межсистемных взаимодействий требует минимум два репозитория.

## Интерфейс

- Карточки стандартных мастеров помечены как «Один репозиторий».
- Они открывают однорепозиторную форму, а не форму рабочей области.
- В форме рабочей области стандартные однорепозиторные профили больше не предлагаются.
- CLI preview и фактический запуск строятся из одного backend-плана.

## Совместимость

- Существующие технические `job_id`, `system_id` и `revision_id` не изменены.
- Старые задания остаются доступными в истории.
- Новое поведение применяется только к новым запускам мастеров.
- Legacy-режим, автоматически оборачивающий одиночный репозиторий в workspace, не сохранялся.
