# Analysis UI 2.0.0a49

## Исправления мастера добавления атрибута

- SQL-витрина с одним репозиторием запускается через `static-analysis-runner repository`, а не через несовместимый `workspace`.
- Для workspace модели данных по умолчанию передаются `--duckdb-memory-limit 1GB` и `--duckdb-threads 1`.
- Логический `repository_id` внутри результатов анализа стабилен и не содержит хеш каталога checkout; хеш используется только для внутреннего runtime-каталога.
- Мастер заранее отклоняет несколько SQL-репозиториев с понятным сообщением, пока Runner не поддерживает их общий SQL workspace.

## Наблюдаемость

- Строки `stderr` классифицируются по содержимому: обычный прогресс — `INFO`, предупреждения — `WARNING`, реальные ошибки — `ERROR`.
- Git-прогресс с carriage return разбивается на отдельные записи.
- При падении стадии в job failure и карточку прогресса переносится последняя безопасная ошибка subprocess.
- Финальная запись явно различает локальную регистрацию артефактов и публикацию revision в Knowledge API.
