# Analysis UI 2.0.0a57

## Фактический прогресс анализа

Фиксированная шкала «Клонирование → Профилирование → Анализ → LLM Pipeline → Отчёт» удалена. Задание публикует только фактически применимые стадии, сформированные backend для конкретного мастера и источников.

Канонические стадии:

- подготовка репозитория или репозиториев — только когда Git checkout действительно будет выполняться;
- статический анализ с пользовательским названием конкретного мастера;
- формирование базы знаний;
- формирование результата — только когда включено построение отчёта;
- публикация — только когда включена публикация ревизии.

Процент показывается только для измеримого checkout одного репозитория на основе сообщений Git. Для статического анализа, материализации, генерации результата и многорепозиторной подготовки используется честный неопределённый индикатор, текущее время выполнения и фактическая подоперация Runner.

## Несовместимое изменение контракта

Обратная совместимость со старой моделью прогресса отсутствует намеренно:

- удалён `JobProgress.percent`;
- удалены `JobStage.percent_start` и `JobStage.percent_end`;
- обязательны `JobStage.description` и `JobStage.progress_mode`;
- старые payload и сохранённые задания с прежней схемой не нормализуются и не мигрируются.

Перед запуском версии 2.0.0a57 следует использовать новую runtime-базу либо удалить старую историю Analysis UI.
