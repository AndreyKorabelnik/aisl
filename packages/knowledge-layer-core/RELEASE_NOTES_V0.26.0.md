# knowledge-layer-core 0.26.0

Iteration 21 promotes generic storage-reference evidence into the canonical relationship model while preserving the facts-only boundary.

## Changes

- Workspace schema upgraded to `workspace_data_model/v15`.
- Added first-class `model_relationship_storage_reference` materialization.
- Storage references are attached only by an exact, unique `(source object, source field, target type)` match; ambiguous matches fail closed.
- Added `v_model_relationship_storage_references`, `v_model_relationship_logical_identity_members` and `v_model_relationship_canonical_storage`.
- Canonical relationship queries now expose logical identity/version/collocation roles separately from physical storage-record key evidence.
- Preserved target alias, physical key field and expression, binding path, return/reference value origin and provenance.
- Relationship diagnostics upgraded to `relationship_storage_evidence_diagnostic/v2`.
- Physical encoding remains downstream interpretation: no alias normalization, separator, SQL recipe or physical join verdict is generated by KLC.
- Public Knowledge API JSON is intentionally unchanged in this release.
